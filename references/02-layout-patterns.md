# 02 自适应页面骨架与布局模式

本篇把宽屏后台、触屏信息流、对话工作台三类界面的布局骨架统一为一套模式库。动手前先识别任务形态与目标视口，自动套用对应骨架；同一界面需要跨端适配时，按响应式断点逐级降级。视觉 Token 与原子法则见 [01-foundations-and-tokens.md](./01-foundations-and-tokens.md)。

## 一、环境探测与骨架选型

先按下面四个信号判断任务形态，再选骨架；不预设端型标签，以实际交互对象和视口为准。

| 探测信号 | 数据密集型（宽屏） | 触屏信息流型（窄屏） | 对话工作台型（桌面 Agent） |
| --- | --- | --- | --- |
| 核心对象 | 表格、字段、批量记录 | 卡片流、条目、媒体内容 | 会话消息、工具调用、产物 |
| 典型视口 | ≥1024px 宽屏 | ≤480px 竖屏手机 | 桌面窗口，可分栏 |
| 操作节奏 | 检索、筛选、批量处理 | 拇指滑动浏览、单点操作 | 流式等待、授权介入、产物消费 |
| 首选骨架 | 第二节 | 第三节 | 第四节 |

跨端响应式后台同时适配窄屏时，以宽屏骨架为基线，按第五节断点逐级降级。

## 二、数据密集型骨架（宽屏后台 / SaaS 工作台）

### 1. 列表页（List Page）

```text
PageLayout
├── PageHeader（页面标题 + 核心统计 + 新建主按钮）
├── FilterPanel（查询条件 + 下拉筛选 + 重置/查询）
└── DataSection（白底主容器）
    ├── SectionToolbar（数据总数 + 导出/刷新 + 视图切换）
    ├── DataGrid / Table（结构化数据 + 状态 Badge + Ghost 操作按钮）
    ├── Pagination（分页器）
    └── BulkActionBar（多选浮动操作条，仅选中时滑出）
```

**五种分支类型**：

| 页面类型 | 布局特征 | 最佳场景 |
| --- | --- | --- |
| 查询表格 Query Table | 顶部筛选 + 密集型表格，单列 6–10 字段 | 财务流水、订单中心、设备台账、数据报表 |
| 标准条目列表 Standard List | 摘要、责任人、进度、阶段，可展开或跳详情 | 任务待办、缺陷追踪、审批流水 |
| 卡片/看板列表 Card Grid | 3–4 列栅格卡片，封面/名称/状态/快操作 | 敏捷看板、设计资产库、商品货架、项目大厅 |
| 搜索列表 Search List | 全局大搜索置顶，高亮片段铺开 | 知识库检索、帮助中心、文档资料库 |
| 成员权限管理 Member Admin | 左部门组织树 + 右用户列表与角色分配 | 企业通讯录、团队管理、RBAC 权限矩阵 |

**查询分层与防卡死**：
- 高频筛选（≥80%）平铺常驻 3–4 个核心条件，按频次从左到右；低频 10+ 维度收拢进“更多筛选”抽屉或折叠面板；高频组合可保存为视图（本地记忆 → 个人私有 → 团队共享）。
- 数据量 <1000 条且索引覆盖：字段改变即实时刷新；>10000 条或慢查询：**必须显式提供「查询」「重置」按钮**，严禁每改一个筛选就全局转圈锁定。
- 时间区间：预设「今天/近 7 天/近 30 天/本月」胶囊 Pills 外露；双日历联动选跨度并设最大跨度防呆；未来日期置灰；统一 `YYYY-MM-DD HH:mm:ss`。
- 树形多选按父级自动收拢，超出宽度收敛为 `+N` 徽标，禁止铺出几十个标签撑爆输入框。

### 2. 表单页（Form Page）

**复杂度四梯度**：
1. 基础单列纵向（<6 字段，单列自上而下）；
2. 弱分组同行（省/市/区、姓/名、单价/数量等强相关短字段，仅此允许同行）；
3. 区域分组（8–15 字段，带标题白底卡片或灰底块语义分区）；
4. 分步向导 Stepper（有明确先后因果：选方案 → 填主体 → 绑支付 → 确认发布）。

**交互铁律**：中文后台首选 Top-aligned 标签置顶；失焦（OnBlur）即时单字段校验，严禁提交时爆出 10 个红框；表单已修改（isDirty）时，切侧边栏或关标签页必须弹离开确认防丢。

### 3. 详情页（Detail Page）

```text
PageLayout
├── DetailHeader（返回链路 + 对象名称 + 状态 Badge + 核心操作栏）
├── MetricsRow?（总金额、总耗时等关键快照）
├── DescriptionGrid（稳定静态基础属性栅格）
└── TabsContainer（复杂维度辅助页签：业务明细 / 审计时间线 / 附件配置）
```

| 详情类型 | 场景 | 布局重点 |
| --- | --- | --- |
| 基础单据详情 | 简单订单、用户信息、设备单页 | DescriptionGrid + 1–2 信息卡片平铺 |
| 高级协同详情 | CRM 商机、客户画像、复杂项目单页 | 顶层基础属性 + 底部 Tabs 切分业务视角 |
| 审批流单据详情 | 报销、请假、采购核决 | 顶部审批阶段时间线，底部常驻“同意/驳回”操作栏 |

### 4. 数据看板与工作台（Dashboard）

```text
PageLayout
├── WorkbenchHeader（问候语 + 今日核心待办统计）
├── KPI Metric Cards（3–4 个核心指标卡，当前值 + 同环比趋势）
├── Charts Section（趋势折线 / 结构饼图 / 漏斗图）
└── QuickAction & RecentActivity（左快捷入口，右最新动态）
```

- 指标卡控制 3–4 个，统一时间口径，禁止一屏塞 12 个指标；图表必须能回答具体业务问题，优先轻量 DOM/CSS 或稳定封装，不引入超 1MB 冗余图表库。
- 数值跨度超 100 倍时启用局部放大（Data Zoom）或对数坐标，防矮数值贴地。

**图表视觉聚焦规则**：

- **重点高亮**：同组多条数据只让最重要的一条用品牌深色/高亮色，其余系列降为浅灰或低饱和；禁止所有系列同饱和度彩虹色并列，重点无法跳出。
- **直接标注替代图例**：线、柱、扇区旁边直接写出名称与数值；仅在系列超过 5 个或标注会互相遮挡时才保留图例。看图人不必在图例与图形之间来回对照。
- **数值对齐**：表格与图表内的数值列右对齐，启用等宽数字（`tabular-nums`），一列数字扫一眼即可比大小。

### 5. 设置页（Settings Page）

左侧设置分类导航（SubNav）+ 右侧内容卡片双栏。
- 自服务个人偏好（深浅模式、通知选项）：Switch/Radio，改后立即自动保存 + 微 Toast“设置已更新”；
- 系统核心规则（手续费率、发票抬头、API Key）：完整表单，必须显式点底部“保存更改”主按钮，防误触震荡全站规则。

### 6. 登录 / 认证页（Auth / Sign-in Page）

登录页是用户对产品的第一印象；相比裸账号密码框，应在行业属性、视觉氛围与实用性之间取得平衡。宽屏默认左右分栏：一侧突出行业场景，另一侧集中登录表单。

```text
AuthLayout（左右分栏，宽屏 ≥1024px）
├── ScenePanel（左：行业场景视觉）
│   ├── 业务场景插画 / 产品主视觉
│   ├── 行业配色氛围与克制光效
│   └── 品牌标识与一句话价值主张
└── FormPanel（右：登录表单）
    ├── 产品名 / 欢迎语
    ├── 账号输入（手机号或账号名）
    ├── 密码输入（可见性切换）
    ├── 验证码 / 二次校验（按需）
    ├── 记住我 + 忘记密码（同行分流）
    ├── 登录主按钮（唯一 Primary）
    └── 注册 / 其他登录方式入口
```

**分栏原则**：
- 一侧突出行业场景，另一侧集中登录表单；两侧视觉重量平衡。表单侧控件统一沿用既有输入框、按钮、字体与间距 Token，不另起一套样式。
- 场景侧只承担氛围与业务识别，不放可交互控件；配色与插画元素服务于行业属性，而非单纯堆砌科技感。

**行业视觉映射**（按业务选配色与元素，可替换为自有场景图）：

| 业务方向 | 主色调倾向 | 场景元素 |
| --- | --- | --- |
| 医疗健康 | 浅蓝 + 薄荷绿，清爽柔和 | 医疗图标、健康数据、柔光效，传达专业、清爽、安全 |
| 社区 / 安防 | 中性稳重 + 安防点缀 | 建筑、安防监控、门禁、安全防护元素 |
| 物流调度 | 蓝 + 橙，活力科技 | 物流园区、运输车辆、配送路线、调度轨迹 |
| 能源电力 / 新能源 | 蓝 + 绿 | 风电、光伏、电网、清洁能源与智慧运营 |
| 农业 / 工厂 / 气象 | 贴合行业的低饱和色 | 作物、厂区、天气仪表等业务符号 |
| 低空经济 / 水利监测等新场景 | 行业主色 | 飞行器、水系监测等场景符号 |

**克制与层级**：
- 好登录页不靠堆砌复杂科技元素（大面积粒子、霓虹、炫光）；适当留白、清晰视觉层级、贴合业务的场景表达，即可简约、专业、有品质。
- 表单侧信息层级：欢迎语 → 账号 → 密码 → 辅助选项 → 主按钮；一屏仅一个实心登录主按钮，忘记密码 / 注册用次级文字链接。
- 错误提示紧贴对应输入框（行内校验），不在提交后集中爆红框；登录加载期锁定主按钮，防重复提交。

**窄屏降级**：<768px 隐藏左侧场景面板，或收成顶部窄品牌横幅；表单单列全宽居中，主按钮全宽；安全区遵循第三节触屏规则。

## 三、触屏信息流骨架（App / 小程序 / H5）

```text
1. 信息流列表 Feed List：吸顶搜索 + 分段 Tab + 单列/双列卡片 + 触底无限加载
2. 沉浸式图文详情 Media Detail：顶部透明/渐变导航 + 轮播大图 + 底部固定 CTA
3. 紧凑表单向导 Form Wizard：单屏 3–5 项输入 + 标签靠左/置顶 + 底部全宽按钮
4. 个人中心与九宫格 Profile：头部资产大卡 + 横向指标组 + 分组圆角单元格列表
5. 空态与异常页 Empty & Exception：简洁插画 + 原因说明 + 单一主行动出口
```

### 信息流性能

- 列表超 50 条必须虚拟滚动（Virtual List），仅渲染可视窗口内 8–10 个 DOM，上下节点回收复用；
- 图片懒加载：进视口前柔和占位底色，进入 150px 内再拉真实资源，使用 WebP 压缩。

### 图片三段式裁切

| 原图高宽比 H:W | 形态 | 裁切策略 | 场景 |
| --- | --- | --- | --- |
| > 4/3 | 高图/竖屏长图 | 裁上下两端，4:3 或 3:2 竖直比例 | 晒单、人像写真、海报 |
| 3/4 – 4/3 | 标准方图 | 1:1 正方形居中裁切 | 商品主图、外卖菜品、头像 |
| < 3/4 | 宽幅扁图/横照 | 16:9 或 4:3 横图居中 | 资讯封面、视频封面、横幅 Banner |

### 底部常驻操作栏

- 容器高 56–64pt + 底部安全区（全面屏 34pt）；
- 单一强动作：全宽圆角主按钮（44–48pt 高，圆角 8–12pt 或全圆角）；双动作分流：左辅助次色胶囊、右强强调品牌胶囊，左浅右深；
- 背景高模糊毛玻璃（blur 16px）+ 半透明白底 `rgba(255,255,255,.9)`，上方 0.5px 微边框；
- **出海百分比切割法**：底部栏切两截，左侧辅助区五档定宽（72% / 43% / 28% / 13% / 0%），右侧按钮 `flex:1` 弹性填满；极端超长词先压纯动词，仍放不下换通用图标。

### 空间决策视角预览（选座/订房/预约）

严禁只给抽象二维网格让用户盲猜；点击目标位置时，上方或浮窗实时联动渲染该位置看向前方的真实视角预览（或 3D/全景视口），交代视角偏角、距离与潜在遮挡，降低决策焦虑与退改率。

## 四、对话工作台骨架（桌面 Agent / AI 应用）

### 1. 任务形态决定空间拓扑

设计前先明确用户核心任务与操作对象，再决定会话气泡、结构化表单、工作台面板与产物画布的位置：

- **目标澄清与探索**：流式对话推进，用语言灵活性迅速收敛模糊需求；
- **高频编辑与精确调参**：必须提供 GUI 结构化控件（滑块、分段器、表单），避免来回打字的低效沟壑；
- **产物消费与协同修改**：聊天气泡建议、预览视图临时渲染、最终落盘对象之间必须有清晰视觉边界；
- **画布空间 Canvas**：多对象关联或空间编排；画布元素作为对话上下文时必须有明确高亮选中提示，杜绝让用户猜测 Agent 读取的是全局还是局部。

### 2. 四层正交分层（严禁压入单列气泡流）

1. **主对话层 Conversation**：用户原始意图表达与 Agent 最终结论回复；
2. **思考与过程层 Reasoning & Process**：可折叠时间轴，流式生成时展示简明阶段标签（“正在检索相关代码…”），完成后收拢为轻量摘要，不占首屏主视线；
3. **工具执行卡 Tool Execution Card**：每次工具调用的发起、参数输入、执行状态、返回结果封装在同一张独立卡片内，严禁每个事件零散打印一行系统文本；
4. **产物层 Artifacts / Workspace**：大段代码、Markdown 报告、交互原型、设计稿独立开辟在右侧或专用工作台面板，支持独立滚动、版本切换、本地保存与全屏放大。

### 3. 组件职责边界

| 组件类型 | 核心状态职责 | 严防错误 |
| --- | --- | --- |
| Tool Execution | 调用标识 ID、输入参数、执行进度、成功结果或错误原因 | 每事件零散打一张卡；把接口已受理误标为已执行完成 |
| User Approval | 拟执行操作、影响范围、目标文件列表、允许/拒绝 | 只问“是否同意”，不展示具体文件路径或命令 |
| Plan / Roadmap | 总体步骤清单、当前进行中、已完成 | 把模型文本里的 `- [ ]` 错当成系统执行证据 |
| Artifact / Diff | 代码/文档差异、单向合并、整文件预览、一键导出 | 预览成功直接误判为本地文件已写入落地 |

### 4. 多会话与多线程管理

- 线程切换隔离：各线程未发送草稿、附件上下文、运行中任务严格隔离并持久化，不因组件卸载丢失；
- 后台任务可观测：后台线程进入等待授权或出错时，侧边栏对应条目有轻量红点或徽章；
- 连接恢复与幂等：断网或重开窗口后优先拉服务端权威快照恢复界面，禁止前端无脑重放可能有破坏性副作用的请求。

## 五、响应式自适应降级断点

| 视口宽度 | 宽屏骨架降级规则 |
| --- | --- |
| ≥1440px | 三–四栏并排；多列指标卡、侧边树 + 列表 + 详情三栏可同时展开 |
| 768–1280px | 上下堆叠双栏；侧边树与列表收进抽屉；指标卡两列 |
| <768px（窄屏） | 图表简化维度；指标卡单列；复杂表格转纵向结构化卡片流；抽屉取代双栏；底部 TabBar 取代侧边导航 |

- 超宽表格包裹在自身容器内滚动，**严禁导致整个浏览器主页面出现横向滚动条**；
- 小视口先保证主键识别列与操作列可见，次要字段响应式断点隐藏，严禁半截遮挡且无法横滚；
- 窄屏下不照搬桌面多列网格与复杂表格，优先第三节触屏信息流骨架。
- **响应式验证断点**：必须在 320px、768px、1024px、1440px 四个宽度逐一走查布局；窄屏移动优先（mobile-first）向上扩展，而非桌面成型后再向下裁切——后补响应式成本约为起步就做的三倍。

## 六、空态、加载态、错误态与受限态

任何可变区块交付前必须逐一验证五种状态均有合理承载：

1. **理想态 Ideal**：数据丰满、正常流转；
2. **空态 Empty**：严禁只留死表头；说明为什么为空，并提供后续行动（“暂无客户数据，[立即录入首个客户]”；筛选无果提供“清除筛选条件”）；
3. **加载态 Loading**：组件自带 loading 遮罩或骨架屏；<1 秒不用骨架屏，>2 秒用带文案指示器；
4. **错误态 Error**：说明错误发生在何处，提供“重新加载”重试；严禁把底层堆栈错误抛给普通用户；
5. **部分/权限受限 Partial / 403**：字段脱敏或整区需申请权限，提供“申请查看权限”入口，严禁用 404 或死白屏掩盖。

整页异常（404/403/500）四要素：情境配图、错误代码与简短定性、大白话原因说明、至少两个明确出口（返回上一页 / 回到工作台）。

## 七、高频布局反模式

- 严禁卡片套卡片（外层白卡内再套带边框白卡）；
- 页头必须独立处于工作区顶端，不可缩进到内部表格白卡；
- 列表数据超 10 条必须提供基本模糊搜索与状态下拉，杜绝无筛选死表格；
- 必须接入规范分页器（总数统计 + 每页条数切换），禁止手写粗糙分页；
- 复杂弹窗、伸缩分栏、拖拽交互复用成熟组件库，不从零手写；
- 已有成熟组件库时，严禁用原生 div 手搓弹窗、折叠面板、复杂拖拽与树控件。

## 八、演示页骨架（PPT / 汇报 / 路演）

面向投屏与演讲的页面，核心是让观众一次只记住一件事，规则与 Web 页面同源，但信息密度更低、字号更大。

- **一页一个观点**：每页只讲一件事，用一句话当标题；一个页面塞不下的论点拆到后续页，禁止一页堆砌多个并列结论。
- **字少图大**：每页正文不超过 3 行，配一张大图、一个大数字或一张大图表；标题与大数字承担视觉主体，正文退为辅助说明。
- **对齐网格**：标题、正文、图片、图表对齐到同一组网格线与边距，翻页时画面稳定，不逐页错位。
- **母版统一**：先定共用底板——标题位置、页码、配色、字体、Logo 位置全站统一，每页套用同一母版；整份演示看起来出自同一人之手。
- **层级对比**：标题放大加粗，说明文字变小变灰；一页只突出一个核心数字或一张主图，不平均用力。

## 九、官网落地页与 Bento 便当盒布局

### 1. 落地页视觉收敛

- **品牌色唯一**：全站只认一个主色，其余文字、背景、分隔用黑白灰中性阶；颜色一收页面立刻干净，禁止功能区各用一种彩色。
- **视觉层级先行**：标题放大加粗，说明文字变小变灰；一屏只留一个实心主按钮，一眼知道先看哪、点哪。
- **区块留白**：间距统一走 4px 网格（8 的倍数优先）；大区块之间留 80–120px 纵向间距，内容不减但页面透气。
- **圆角与阴影克制**：卡片圆角统一（16px 档），阴影只用很淡的一层；卡片立得住但不脏、不堆叠多重投影。

### 2. Bento 便当盒布局

- 功能区由大小不一的格子拼在一起（Bento Grid），最重要的功能占大格子，次级功能占小格子，形成明确主次；禁止所有卡片等大平铺成呆板网格。
- 格子之间用统一间距与微边框切分；大格可放主产品图/主指标，小格放次级功能入口。
- **微交互收尾**：鼠标悬停卡片轻轻浮起，下滑时内容一块块错峰出现；每个可点动作都有回应，页面才“活”，但反馈遵循 04 篇动效铁律，克制不喧闹。

## 十、参考图转设计契约

当产品需要明确视觉方向、手头有外部参考稿（官网、竞品、作品截图）时，先收集证据再定布局，把参考屏提炼为本项目可执行的设计契约，而不是照着截图复刻。

1. **选取样本**：从可信参考集或产品团队提供的资料中，研究 2–3 个相关参考屏，不求多，求代表性。
2. **记录决策**：逐屏记下信息层级、内容密度、导航方式、控件形态、响应式表现与各交互状态（默认/悬停/按压/禁用/加载/空/错）。
3. **落成简短设计契约**：实现前先写清——本屏职责是什么、主操作是什么、需要覆盖哪些状态、响应式规则、明确拒绝的模式（不照搬的布局与交互）。
4. **重建到自身体系**：把可复用的结构映射回本项目自己的组件、设计 Token、文案与视觉语言；**严禁复制他方品牌标识、专有文案、图片素材或精确布局**。
5. **参考是证据不是模板**：没有参考时，先记录所做假设，并对照项目既有设计系统校验结果；参考与现有体系冲突时，以本项目既定 Token 为准。
