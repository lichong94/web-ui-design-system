## 一、设计哲学与三效协同

1. **Linear / Apple Notes 标准**：像 Linear 官网或 Apple Notes 一样纯粹克制——简单目的、简单架构、简单设计、简单实现。
2. **空间即解释**：删除标语、辅助文本和次要标签，让布局、信息密度与视觉层级自身完成解释；一个页面必须靠辅助文案才能看懂时，不加字，去修复布局。
3. **UX × DX × AX 三效协同**：每个架构或视觉决定同时提升：
   - **UX（用户体验）**：低认知负荷、高扫描效率、零误操作；
   - **DX（开发者体验）**：组件语义唯一、4px 栅格可预测、无散落硬编码；
   - **AX（智能体体验）**：外置确定性变量契约（Design Token）与脚本门禁，AI 协作不靠死记硬背、不漂移，拼装即正确。

## 二、色彩变量体系

### 1. 颜色分层架构

| 层次 | 变量前缀 | 说明与用法 |
| --- | --- | --- |
| 基础色盘 (Palette) | `--color-blue-500` 等 | 物理色值阶梯（100–900），业务代码禁止直接使用 |
| 语义 Token (Semantic) | `--color-brand-primary` 等 | 赋予功能职责，业务代码必须使用此层 |
| 组件级 Token (Component) | `--btn-primary-bg` 等 | 组件内部定制重写，默认引用语义 Token |

### 2. 中性色微倾向法则

纯黑灰（`#000000` / `#808080`）显得沉闷死板。中性灰阶必须带微弱主题倾向：偏科技蓝品牌混合 2%–4% 冷蓝（slate/zinc）；偏温暖品牌混合极微弱暖灰（stone）。

### 3. 核心语义 Token 参考

```css
:root {
  /* 页面与表面底色 */
  --color-bg-canvas: #f8fafc;      /* 整个 App 页面底色 */
  --color-bg-surface: #ffffff;      /* 卡片、表格、面板承载面 */
  --color-bg-subtle: #f1f5f9;       /* 斑马纹、标签底、输入框悬浮 */
  --color-bg-muted: #e2e8f0;        /* 禁用态背景、次级分割区 */

  /* 文字层级（对比度达 WCAG AA 以上） */
  --color-text-primary: #0f172a;    /* 主标题、正文、强强调 */
  --color-text-secondary: #475569;  /* 次要信息、表头、属性标签、说明 */
  --color-text-tertiary: #94a3b8;   /* 占位符、辅助图标、不可用提示 */
  --color-text-disabled: #cbd5e1;    /* 禁用文字 */

  /* 边框体系 */
  --color-border-subtle: rgba(226, 232, 240, 0.8);
  --color-border-default: #e2e8f0;
  --color-border-hover: #94a3b8;
  --color-border-focus: #3b82f6;

  /* 品牌主色 */
  --color-brand-primary: #2563eb;
  --color-brand-hover: #1d4ed8;
  --color-brand-active: #1e40af;
  --color-brand-subtle: #eff6ff;

  /* 状态语义色（四态） */
  --color-status-success: #16a34a;  --color-status-success-bg: #f0fdf4;
  --color-status-warning: #ea580c;  --color-status-warning-bg: #fff7ed;
  --color-status-danger: #dc2626;   --color-status-danger-bg: #fef2f2;
  --color-status-info: #0284c7;     --color-status-info-bg: #f0f9ff;
}
```

## 三、0.5px 精细微边框

- **拒绝粗黑边框**：现代高级感来自轻盈、通透、边界分明却不抢视觉重心；杜绝浓重的 `1px solid #ccc`。
- **标准配方（半透明微边框，首选）**：
  ```css
  .border-subtle { border: 1px solid rgba(226, 232, 240, 0.7); }
  ```
- **Retina 级物理 0.5px 分割线**（卡片组、列表横线）：
  ```css
  .hairline-b { position: relative; }
  .hairline-b::after {
    content: ""; position: absolute; left: 0; bottom: 0; right: 0; height: 1px;
    background-color: var(--color-border-subtle);
    transform: scaleY(0.5); transform-origin: 0 100%;
  }
  ```
- 多密度适配：@2x/@3x 高清屏上 `1px` 会渲染成 2–3 物理像素粗线，必须采用上述半透明微边框或物理 0.5px 缩放配方。

## 四、同心圆角与光学对齐

### 1. 同心圆角几何法则

外层与内层圆角相同会出现内角太尖或留白不匀的挤压缺陷，必须满足：

$$R_{outer} = R_{inner} + Padding$$

外层内边距 16px、内部按钮圆角 6px 时，外层圆角应为 22px 左右；卡片圆角 12px、内边距 12px 时，内层圆角为 0（平直）或至多 4px。

### 2. 全局圆角 Token

```css
:root {
  --radius-none: 0px;  --radius-xs: 2px;  --radius-sm: 4px;
  --radius-md: 6px;   --radius-lg: 8px;   --radius-xl: 12px;
  --radius-2xl: 16px;  --radius-full: 9999px;
}
```

| Token | 数值 | 适用场景 |
| --- | --- | --- |
| `radius-none` | 0px | 贴边栏、全屏模块、连体按钮中段 |
| `radius-xs` | 2px | 微型徽标、极小指示器 |
| `radius-sm` | 4px | 输入框、下拉框、紧凑按钮、代码块 |
| `radius-md` | 6px | 标准按钮、Toast、气泡卡片 |
| `radius-lg` | 8px | 弹窗、抽屉内部模块、下拉浮层菜单 |
| `radius-xl` | 12px | 业务卡片、KPI 指标卡 |
| `radius-2xl` | 16px | 顶层悬浮面板、独立弹窗主容器 |
| `radius-full` | 9999px | 头像、胶囊徽标、开关滑块 |

条件允许且性能无忧时，优先使用连续圆角（Squircle / 超椭圆曲率），消除纯圆弧转折点的曲率突变。

### 3. 光学视觉重心

- 拒绝机械居中：图标通常比字母视觉体量更大，图标+文字按钮需按视觉重心做 1–2px 光学微调；行内图标下沉 `translate-y-[0.125em]`（1/8 字高）与文字 x-height 咬合。
- 模态弹窗严禁垂直正中 50%（会产生下坠错觉），上浮至视口高度 **38.2% 黄金分割位**，或 `margin-top: max(80px, 15vh)`。

## 五、阴影层级与防裁切余量

### 1. 现代柔和弥散投影

```css
:root {
  --shadow-none: 0 0 #0000;
  --shadow-card: 0 1px 3px 0 rgba(15,23,42,.04), 0 1px 2px -1px rgba(15,23,42,.04);
  --shadow-popover: 0 4px 6px -1px rgba(15,23,42,.06), 0 2px 4px -2px rgba(15,23,42,.05);
  --shadow-dialog: 0 20px 25px -5px rgba(15,23,42,.08), 0 8px 10px -6px rgba(15,23,42,.04);
}
```

### 2. 阴影被裁切硬门禁（高频致命 Bug）

带阴影的元素被父级 `overflow: hidden/auto`、`clip-path` 裁成半截时：
- 阴影元素到任意裁切祖先内壁的间距，必须满足：**Margin/Padding ≥ OffsetY + Blur + Spread**；
- 余量不足时，严禁在内层挂深投影：将投影移至外层无裁切容器，或内层降级为纯 0.5px 微边框；
- 内外分层原则：负责圆角裁切的容器放内层，负责投影光效的容器放外层。

## 六、4px 间距网格

全站间距严格以 **4px 的倍数**作为唯一步进，严禁 `10px / 14px / 18px / 22px` 等非 4 倍数随机值；元素嵌套必要时保持上下左右内边距一致（Symmetric Padding）。

| Token | 数值 | 语义用法 |
| --- | --- | --- |
| `space-1` | 4px | 图标与文字间隙、内联标签小间距 |
| `space-2` | 8px | 紧凑行距、按钮图标与文本间距 |
| `space-3` | 12px | 表单项间距、卡片紧凑内边距 |
| `space-4` | 16px | 标准容器内边距、按钮两端留白 |
| `space-6` | 24px | 卡片间隙、区块纵向隔离、弹窗内边距 |
| `space-8` | 32px | 页面大模块分隔、空状态留白 |
| `space-12` | 48px | 主内容区与导航的大留白 |

## 七、排版字阶（自适应宽/窄/桌面）

### 1. 宽屏 Web 与后台字阶

| 级别 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| Page Title | 20px / 28px | 600 | 页面一级主标题 |
| Section Title | 16px / 24px | 600 | 卡片大标题、模块标题、弹窗主标题 |
| Content Body | 14px / 20px | 400 | 核心正文、表格数据、表单值 |
| Content Bold | 14px / 20px | 500 | 表头、关键字段名、高亮数值、主按钮文字 |
| Caption / Help | 12px / 16px | 400 | 校验提示、次要说明、时间戳、徽标文案 |

### 2. 桌面 Agent 字阶

推荐三档：辅助微文本 12px + 正文/输入 13–14px + 模块标题 16px；**最小可用文字门禁 12px**，严禁更小字号损害可读性。

### 3. 移动端字阶

基于逻辑点（pt/dp）：导航栏标题 17pt Semibold，展开大标题 34pt Bold；正文 14–16pt，辅助说明 12–13pt；Android 用 `sp` 随系统字号缩放，iOS 用 `pt` 并支持 Dynamic Type。

### 4. 通用排版微细节

1. **暗色模式字重补偿**：黑底白字存在光晕扩散错觉，Dark Mode 下全局主字重自动下调一档（500→400，600→500），以代码参数差异换取视网膜感知粗细一致。
2. **等宽数字锁死（Tabular Numerals）**：监控指标、KPI、表格数值、倒计时、金额、Agent 耗时与 Token 速率，全量启用 `font-variant-numeric: tabular-nums`，消除数字跳动时的左右乱颤。
3. **防孤字成行**：主标题、卡片标题、引导文案启用 `text-wrap: balance`，杜绝末行孤零零掉下单字。
4. **层级靠字重不靠堆字号**：信息层级优先通过字重（400/500/600）、灰阶对比与间距表达；全页字号严格控制在 3–4 档以内。
5. **移除冗余 UX 文案**：只留核心标题与关键键值对；删除标语、占位副标题与无意义悬顶小标签（eyebrow）；说明文字书面严谨，严禁营销腔或轻浮口语；低频说明用 Tooltip / 可关闭 Alert / 折叠面板按需收纳，不常驻干扰。
6. **标题层级不跳级**：`h1` 每页仅一个页面主标题，向下依次 `h2` 分区标题、`h3` 子区标题、正文、辅助小字；严禁跳过层级（h1 直跳 h3），也严禁把非标题内容（按钮文字、卡片标签、强调值）套标题样式。

## 八、按钮完整六态与五档层级

### 1. 完整六态

生产级可用按钮必须完整实现以下 6 态，AI 生成时常漏掉 Loading 与 Focus-visible：

| 状态 | 触发时机与表现 | Do | Don't |
| --- | --- | --- | --- |
| Default | 未接触态，一眼可识别为可点按键 | 填充/边框语义清晰 | 把主操作做成无边框纯文本 |
| Hover | 鼠标移入，颜色微深 + `cursor-pointer` | 150ms 内即时反馈 | 划过毫无动静逼用户试错 |
| Active | 按住未松手，更深 + 微下沉 `translate-y-[1px]` | 提供按压实感防连点 | 无物理反馈导致用户连戳 |
| Disabled | 前置条件未满足，置灰 + `cursor-not-allowed` | 明确不可点且保持可读对比度 | 看似可点却毫无响应（假卡死） |
| Loading | 异步等待 >1 秒，内嵌 Spinner 并锁死防重 | `disabled={isLoading}` + 文字切“处理中…” | 只转圈不锁点击，引发重复提交/扣费 |
| Focus-visible | 键盘 Tab 命中时外亮聚焦框 | `focus-visible:ring-2`（仅键盘可见） | 全局写 `outline: none` 抹掉聚焦外框（违反 WCAG） |

> Hover 服务鼠标，Focus 服务键盘，二者不可互相替代。触屏设备无 Hover，以 Active 按压态反馈为准。

**按压缩放反馈**：所有可按压元素（按钮、卡片、可点条目）`:active` 叠加 `transform: scale(0.97)`（幅度 0.95–0.98），配合 160ms `--ease-out`，即时给出界面“已听见操作”的实感；`scale()` 会连带等比缩放内部文字与图标，这是特性而非缺陷，无需再单独处理子元素。

### 2. 五档视觉层级

| 变体 | 视觉特征 | 适用场景 | 关键约束 |
| --- | --- | --- | --- |
| `primary` | 实心高饱和品牌色 | 操作区最高频、最推荐的核心主任务 | **一个操作区严禁 2 个及以上 primary** |
| `secondary` / `outline` | 浅底或 0.5px 描边 | 辅助操作、取消、重置、导出 | 并列次操作统一用此变体 |
| `ghost` / `text` | 无背景无边框，仅文字+悬浮微底 | 表格操作列每行动作、次级折叠触发 | 节省横向空间，不打扰数据扫读 |
| `danger` | 醒目红色（填充或描边） | 删除、停用、清空、注销、中断等高危操作 | 禁止用 primary 涂红替代；高危配二次确认 |
| `link` | 纯文字带外链跳跃语义 | 跨页面跳转、第三方文档 | 当前页操作严禁用 link 假扮按钮 |

**主操作判定五步法**：统计频次找最高频动作 → 低频/高影响动作降权进“更多” → 审批与责任决策区不设主按钮（双方均次级，保持中立）→ 状态联动时主操作可动态切换但同一时刻仅一个 → “更多”菜单只剩 1–2 项时直接平铺。

### 3. 有手感控件微交互四模式

描述按钮/开关微交互时，必须写清**触发顺序、形变数值、颜色变化、时长、缓动曲线与反馈元素**；只说“做个好看的按钮”“加个加载状态”“做个开关”，结果只会得到一个会变色的方块。四个常用具名模式及其参数契约：

| 模式 | 交互序列与参数 | 适用场景 | 约束与禁忌 |
| --- | --- | --- | --- |
| Like Burst 点赞爆粒子 | 点击后爱心先压扁到 0.8 → 弹到 1.2 → 回稳 1；由灰变红；周围炸开 5–8 个小圆点向外飞出；计数数字滚动 +1；时长约 600ms，弹簧回弹曲线 | 点赞、收藏、喜欢等情感反馈 | 粒子数量克制不遮挡文字；回弹幅度小；取消点赞反向收回；数字用等宽字体 |
| Submit Morph 提交三连变 | 点击后文字淡出 → 按钮宽度收缩成圆形 → 圆内出现旋转加载圆环 → 约 1.2s 后变绿色对勾 → 再过 1s 恢复原状；收缩 300ms，ease-in | 表单提交、预约确认等单次提交按钮 | 加载期间锁死点击防重复提交；成功对勾用 success 语义色；失败回退原状并给出错误提示 |
| Jelly Toggle 果冻开关 | 圆点滑向另一侧，滑动途中先横向拉长到胶囊形，到达终点后恢复圆形；颜色由灰变绿；时长约 350ms，回弹弹簧曲线 | 设置项开关、通知/偏好切换 | 拉长只发生在滑动途中，落位必须回圆；滑动可中断；关闭态与开启态颜色语义一致 |
| Hold to Confirm 长按确认 | 按住不放，外圈进度环顺时针走满（约 1.5s）才执行；中途松手进度倒退归零 | 可撤销或轻量高危操作（删除单条内容、清空草稿等） | 进度环需显示剩余进度；松开有明确回弹反馈；**删库、注销、巨额扣款等不可逆高危仍走锁死阻断 AlertDialog**，不用长按替代 |

> 微交互性能与降级遵守 04 篇铁律：只改 transform/scale/opacity，时长克制，系统开启减弱动态效果时降为静态切换。

## 九、Badge 徽标业务映射

### 1. 语义与 Variant 强绑定

| 业务语义 | Variant | 背景色 | 文字色 | 示例 |
| --- | --- | --- | --- | --- |
| 正常/完成/健康 | `success` | `#f0fdf4` | `#16a34a` | 运行中、已上线、支付完成 |
| 待办/预警/审批中 | `warning` | `#fff7ed` | `#ea580c` | 待审核、库存紧张、证书临期 |
| 危险/错误/阻断 | `danger` | `#fef2f2` | `#dc2626` | 离线、同步失败、违规封禁、欠费 |
| 中性/常规信息 | `info` | `#f0f9ff` | `#0284c7` | 草稿、队列中、普通备注 |
| 进行中/活跃 | `processing` | `#eff6ff` | `#2563eb` | 正在构建、导入中（可带微动画点） |
| 已停用/次级归档 | `secondary` | `#f1f5f9` | `#475569` | 已下线、已归档、历史记录 |

### 2. 浅底深字 80% 黄金法则

- 纯白字配深红/深绿实心底色冲击过大，密集表格中造成视觉跳跃眩晕；实心底色仅限极小未读红点或灾难级 Alert。
- **严禁只给颜色不给文字**：Badge 内必须写明具体业务状态文案。
- 同一含义全项目只用一个 Variant，禁止“成功”用绿、“已完成”用蓝。
- **Badge 与 Tag 区分**：Badge 表示系统客观状态（单向告知，不可删）；Tag 表示主观分类/元数据（可增删、可筛选联动）。

### 3. 红点三档克制

- 一档（待办审批/未读告警/关键失败）：带具体数字徽标；
- 二档（新功能/次级更新）：6–8px 无字纯圆点；
- 三档（营销推广/常规通知）：严禁挂红点。
- 徽标锚定右上角，数字增多时**向左单向膨胀**，超过 99 收敛为 `99+`。

## 十、去 AI 味四大纯粹性铁律

1. **页面默认平（Zero Shadow on Cards）**：常规卡片、表格容器、表单区域一律纯平，用 0.5px/1px 微边框与微灰背景切分层级；阴影只留给离屏真实浮层（Dropdown / Popover / Modal / Drawer / BottomSheet），杜绝卡片套卡片与滥用发光。
2. **全页仅一个强调色**：除唯一主行动按钮外，其余次要操作、状态 Badge、折叠图标一律收敛为暖中性灰；仅危险警告或成功终态允许少量语义红/绿。
3. **灰用暖灰，字号 ≤4 档**：优先带微温的暖灰阶（Zinc/Stone），禁用冷青灰或纯黑底白字；字号严格 4 档以内：大数字 24/28 → 模块标题 16 → 正文表格 14 → 辅助说明 12。
4. **标题纯粹性与数字格式化**：标题内严禁挑单字刻意着色或倾斜；数字必须带千分位与物理单位，严禁裸露无格式数字。

## 十一、出海国际化与 RTL

### 1. 短词膨胀防护

IBM 本地化实证：中文 2 字概念译为德/荷/法语后长度暴涨 2–3 倍。严禁对操作按钮写死 `w-20` / `width: 80px`；使用 `flex-1` 弹性填充、`min-w-[80px] w-auto px-4` 自适应；出海表单首选 Top-Label 上下结构（Label 在输入框上方，左右空间留给长词）。极端超长词先压为纯动词，仍放不下时降级为通用图标。

### 2. 音标防削顶

泰语、越南语、阿拉伯语、印地语上下带音标声调符号：行高必须 ≥1.5，严禁 `line-height: 1` / `leading-none`；单行容器严禁滥用 `overflow: hidden` 削掉音标。

### 3. RTL 逻辑属性与 LTR 强制特例

阿语等 RTL 界面整体镜像，排版使用 CSS 逻辑属性：`margin-inline-start/end`、`padding-inline-start/end` 替换物理 `left/right`；箭头图标配合 `dir="rtl"` 掉头。以下要素**必须强制保持 LTR**：
1. 视频/音频播放进度条、音量滑块；
2. 国际电话号码、API 端点 URL；
3. 代码块、终端日志与英文技术参数；
4. 纯数字、统计指标、版本号与数学公式；
5. 会话流进度条、模型吐字进度与快捷键提示。

## 十二、AX 智能体协作防退化协议

1. **改过 5 轮未果，果断开新窗**：旧对话被多版错误补丁污染后，切断重开干净白板。
2. **最小充分上下文切片**：向新窗口只投喂报错堆栈、出错的十余行函数及其直接依赖，不整文件倾倒。
3. **规则契约外置真源**：圆角、间距、主色与语义规则写入独立 Token / 规范文件，AI 每次任务开门即读，不依赖口头记忆。
4. **复用成熟组件库组装**：参考 shadcn/ui、Radix、Ant Design 等成熟体系制定 Do/Don't 选型范例，严禁在已有成熟库的项目里从零手搓弹窗、折叠面板、复杂拖拽与树控件。

## 十三、可访问性与语义（WCAG 2.1 AA / ARIA）

### 1. 基础对比度与语义标签

- 普通文本对比度 ≥ 4.5:1，大字号文本（≥18px 常规 / ≥14px 加粗）≥ 3:1；户外高对比场景按 04 篇第十二节加码。
- 色彩只作辅助通道：**严禁只靠颜色传达状态**（红/绿无文字无图标），必须同时配文字、图标或纹理图案。
- 使用语义化原生标签：`button`、`a`、`nav`、`ul/li`、`table` 等；标题层级见第七节。

### 2. 控件与键盘可达

- **原生 `button` 优先于 `div` + `role="button"`**：原生按钮自带焦点、回车/空格触发与读屏语义；确需非语义元素时，必须补 `tabIndex={0}`、`Enter`/`Space` 触发并处理 `keydown/keyup`。
- 所有可交互元素必须可经 Tab 依次到达并操作；打开浮层后键盘焦点移入浮层内部并锁定，关闭后焦点归还触发元素（见 04 篇第十节“焦点管理与历史返回定位”）。
- 菜单、对话框、标签页 Tabs、列表框 Listbox、组合框 Combobox 严格遵循 WAI-ARIA APG 对应模式，不自行发明交互语义。

### 3. 可读标签

- 无可见文字的图标控件必须补 `aria-label`（如仅含关闭叉号的按钮标 `aria-label="关闭对话框"`）。
- 表单输入必须用 `<label htmlFor="输入框 id">` 关联；无可见标签时退而使用 `aria-label`。
- 状态区块（空态、加载中）配 `role="status"`、`aria-busy="true"` 与可读名称，让读屏能传达页面内容与结构。

### 4. 验收基线

交付前应可走查：无控制台错误；Tab 可遍历全部交互项；读屏能传达标题层级、列表与主要操作；除已知未覆盖边界外无 axe-core 可访问性警告。项目自身有 lint/类型/测试命令时优先运行，不为校验另装工具链；跑不了的项需如实说明。
