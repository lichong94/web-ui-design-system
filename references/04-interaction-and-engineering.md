## 一、触控热区与拇指舒适区

手指生理接触面约 8–10mm 不规则椭圆，**视觉元素小不等于触控热区小**。

- **iOS HIG**：最小可交互区域 ≥ 44×44pt；**Android Material**：≥ 48×48dp；相邻可点击项边缘留白 ≥ 8pt/dp。
- 16/20px 小图标（返回箭头、关闭叉、清除按钮）严禁把容器锁死在视觉尺寸：
  ```css
  /* 方案 A：容器保留 44px 热区，内部居中对齐小图标 */
  .touch-target { width: 44px; height: 44px; display: flex; align-items: center; justify-content: center; }
  /* 方案 B：伪元素向外扩张热区 */
  .expand-touch-area::after { content: ""; position: absolute; top:-10px; bottom:-10px; left:-10px; right:-10px; }
  ```

**拇指三层同心圆弧分区**：
- 困难触及区（顶部）：辅助状态、不可点击标题、纯展示数据；
- 伸展触及区：次要操作、搜索框、分类 Tab；
- 舒适自然区（底部）：核心 CTA、底部 TabBar、列表高频点击项、主要输入卡片。

核心转化按钮（保存、立即购买、确认授权）沉底放置在自然舒适区（距底部安全区 12px），严禁孤立放在右上角。长列表上滑阅读时顶部导航栏可平滑上收折叠，用户反拉时立即浮出。

> 鼠标环境以 Hover 反馈为主；触屏环境无 Hover，以 Active 按压态反馈为准。

## 二、安全区避让（异形屏）

异形屏（刘海、灵动岛、打孔、Home Bar）决定内容不能撑满物理边缘。

### 硬件尺寸基线

- 顶部状态栏：iOS 直面屏 20pt，刘海/挖孔 44–50pt，灵动岛旗舰 54–62pt；Android 24–36dp。
- 顶部导航栏：iOS NavigationBar 44pt；Android TopAppBar 56/64dp。
- 底部 Home Indicator：iOS 全面屏 34pt（横屏 21pt）；Android 手势横条 16–24dp（传统三键导航 48–56dp）。
- 底部标签栏：iOS TabBar 83pt（49pt 操作区 + 34pt 安全区）；Android NavigationBar 80dp。

### 工程避让配方

```css
/* 根视口必须声明 viewport-fit=cover */
/* <meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover"> */

.safe-top { padding-top: max(20px, env(safe-area-inset-top)); }
.safe-bottom { padding-bottom: max(16px, env(safe-area-inset-bottom)); }

.fixed-bottom-cta {
  position: fixed; left: 0; right: 0; bottom: 0;
  padding: 12px 16px;
  padding-bottom: calc(12px + env(safe-area-inset-bottom));
  background: rgba(255,255,255,.95);
  backdrop-filter: blur(12px);
  border-top: 1px solid rgba(226,232,240,.7);
}
```

## 三、软键盘治理

软键盘占屏幕 40%–55% 空间，处理不当会遮住输入框、顶碎布局、挡住吸底按钮。

### 遮挡与视口自适应

```typescript
// 聚焦自动居中滚动（延迟 300ms 等键盘弹起动效完成）
const handleInputFocus = (e: React.FocusEvent<HTMLInputElement | HTMLTextAreaElement>) => {
  setTimeout(() => e.currentTarget.scrollIntoView({ behavior: "smooth", block: "center" }), 300);
};
```

```css
/* 表单容器底部弹性垫高，预留软键盘与吸底按钮空间 */
.form-scroll-container { padding-bottom: 350px; overflow-y: auto; -webkit-overflow-scrolling: touch; }
```

### 键盘收起三模式

1. 轻触空白处立即收起（`document.activeElement.blur()`）；
2. 列表拖动即收起（对齐 iOS `UIScrollView.KeyboardDismissMode.onDrag`）；
3. 完成动作自动收起（验证码输满、点“搜索/完成”，触发请求同时收起键盘露出反馈）。

### 表单轻量化

单屏字段 ≤5 项，超出用分步向导或分组卡片折叠；占位符仅展示示例格式，不写大段规则说明；失焦即时局部校验，红字紧贴输入框下方，严禁模态弹窗打断输入心流。

## 四、手势与滚动手感

### 滑动肉感三铁律

1. **1:1 零延迟跟手**：`touchmove` 阶段严禁施加 ease 缓动延迟；
2. **离手动量衰减**：`touchend` 按最后 100ms 初速度抛掷，指数衰减 $v(t)=v_0 e^{-kt}$，不硬切静止；
3. **边界弹簧回弹**：阻尼比 ζ≈0.75（微弱过冲无多余晃荡），有质量的弹簧曲线，禁用机械 linear 或死板 ease-in-out。

```css
html, body { overscroll-behavior-y: contain; -webkit-overflow-scrolling: touch; }
.horizontal-scroll-container { overflow-x: auto; overflow-y: hidden; touch-action: pan-x; overscroll-behavior-x: contain; }
```

### 手势冲突治理

- 最左侧区域放横滑轮播/卡片组时，边缘右滑返回易被劫持；外层边缘预留 ≥16pt 安全间距，或手势判定排除边缘 20pt 内起始触摸。
- Android 14 预测性返回配合水平位移滑动转场，严禁瞬切或黑屏过渡。
- 手势只能当提效捷径，**严禁作为唯一功能入口**：删除/编辑/收藏等核心功能必须有可视化点击按钮；适老大字模式禁用复杂多段手势与横扫，全部还原为大号实体按钮。

### 拖拽 dismiss 与边界阻尼

- **速度阈值优先于距离阈值**：计算 `速度 = |拖拽位移| / 耗时`，速度超过约 0.11（单位长度/毫秒量级）即判定关闭，不论拖出距离；快速一甩就应 dismiss，不必硬拖过固定距离。
- **指针捕获**：拖拽一开始就对元素绑定指针捕获（pointer capture），指针滑出元素边界后拖拽仍连续，不因离界中断。
- **多点触控保护**：拖拽开始后忽略后续新增触点，避免中途换手指导致元素跳到新触点位置。
- **边界摩擦代替硬 stops**：拖过自然边界（抽屉已到顶仍上拉）时施加递增阻尼，越拖越慢，而不是撞到一堵看不见的硬墙。

### 手势设计策略

| 策略 | 表现 | 场景 | 约束 |
| --- | --- | --- | --- |
| 单手操作补偿 | 双击缩放/长按倍速 | 地图、视频全屏 | 向下兼容常规双指操作 |
| 多段式递进 | 按压时长/滑动距离达阈值跃迁 | 长按连赞收藏、下拉进“二楼” | 达阈值触发震动触觉反馈 |
| 行内快捷滑块 | 条目左滑露功能按钮 | 已读/删除、邮件归档 | 滑出宽度 70–140pt，带明确确认 |
| 沉浸式自动避让 | 上滑时导航栏收起 | 长阅读、商品详情 | 反拉即重新浮出 |

## 五、滚动穿透与点击穿透锁死

```typescript
// 浮层展开时锁死 body，关闭时恢复滚动位置
export const lockBodyScroll = () => {
  const scrollY = window.scrollY;
  document.body.style.position = "fixed";
  document.body.style.top = `-${scrollY}px`;
  document.body.style.left = "0";
  document.body.style.right = "0";
  document.body.style.overflow = "hidden";
};
export const unlockBodyScroll = () => {
  const scrollY = document.body.style.top;
  document.body.style.position = "";
  document.body.style.top = "";
  document.body.style.left = "";
  document.body.style.right = "";
  document.body.style.overflow = "";
  window.scrollTo(0, parseInt(scrollY || "0", 10) * -1);
};
```

- 抽屉内部长列表滚到最顶继续下拉判定为关闭抽屉意图（见 03 篇第四节）；
- 浮层关闭淡出动画 200–300ms 期间，遮罩 `pointer-events: none` 阻断穿透；
- 点击穿透防护：统一用 `pointerdown/pointerup` 或框架成熟事件。

## 六、中文输入法（IME）安全发送

中文/日文拼音输入法下，候选词按 Enter 确认选词时，浏览器会在 `compositionend` 同时或数毫秒后紧随抛出 keyCode 13 的伴生 `keydown` 幽灵事件；仅检查 `isComposing` 在高负荷渲染时可能漏掉，导致选词即误发消息。

```typescript
let lastCompositionEndTime = 0;

export function handleCompositionEnd() {
  lastCompositionEndTime = performance.now();
}

export function handleComposerKeyDown(e: React.KeyboardEvent<HTMLTextAreaElement>, onSend: () => void) {
  if (e.key === 'Enter' && !e.shiftKey) {
    if (e.nativeEvent.isComposing) return;           // 原生组字中直接放行
    const elapsed = performance.now() - lastCompositionEndTime;
    if (elapsed < 500) {                              // 伴生幽灵键，拦截并立即复位时间戳
      e.preventDefault();
      lastCompositionEndTime = 0;
      return;
    }
    e.preventDefault();
    onSend();
  }
}
```

- 拦截伴生键后必须立即复位时间戳，杜绝后续正常快速击键被误吞；
- 换行统一 `Shift + Enter`（可配置 `Ctrl/Cmd + Enter` 发送）；
- 附件上传状态细分：正在解析、上传成功、错误重试、已移出上下文。

## 七、自适应增高输入框

### 三层机制

1. **内芯 Textarea**：现代 Chromium 用 `field-sizing: content` 实时跟随文本量；兼容环境用轻量 `ResizeObserver` 监听真实高度；
2. **外容器过渡**：外层显式计算 height 并绑定弹性过渡（Spring 或 Bezier）；外容器保持 `overflow: visible`，允许内芯增高瞬间平滑探出；增高响应迅速、收缩回弹柔和的非对称缓动；
3. **滚动上限与局部滚动条收敛**：明确 `max-height`（240–320px），超出后外层锁定、内层垂直滚动；局部隐藏系统灰色滚动条外观（`scrollbar-width: none` / `::-webkit-scrollbar { display: none }`），同时完整保留滚轮、触控板手势、文本选取与键盘 PageUp/Down 可访问性；**严禁全局禁用滚动条**，仅限定输入框内。

## 八、流式消息视口跟随

模型高速流式吐字时，简单 `scrollIntoView()` 会把向上翻看历史的用户强行拽回底部。

1. **跟随状态判定**：计算 `distanceFromBottom = scrollHeight - scrollTop - clientHeight`，容差阈值 40px；≤阈值为“底部跟读模式”，新内容追加时平滑贴底；>阈值判定“向上回溯阅读”，立即冻结自动滚动，保持视口静止；
2. **回到底部悬浮按钮**：回溯模式且下方有新消息时，右下角悬浮轻量按钮（“有新回复 ↓”），点击平滑回底并重新激活跟随；
3. **高度突变防抖**：代码高亮完成、异步图片加载、折叠面板展开时，计算高度差值补偿 `scrollTop`，防视网膜级抖动。

## 九、分栏拖拽与多窗口一致性

- 分栏拖拽手柄必须有清晰 hover 与 active 视觉反馈；
- **折叠吸附与 Escape 取消闭环**：拖拽至左右极限（≤18% 或 ≥82%）自动吸附；拖拽中途按 Escape，必须三步状态机复位：取消全局监听与 `isDragging` 标记 → 显式 `setIsRightCollapsed(false)` 保留手柄挂载 → 分栏比例恢复拖拽前基准 `previousRatioRef.current`，严防手柄 DOM 卸载导致永久死锁；
- 左右面板必须拥有完全独立的滚动容器，严禁跨面板产生全局水平滚动条。

### 多窗口 Broker-Replica 模式

主窗口作为状态权威 Broker，弹出窗口作为 Replica 订阅不可变状态流；子窗口写入/修改文件对象前先申领乐观基线锁，主进程比对基线版本哈希仲裁冲突，防止并发脏写覆盖。

## 十、桌面工程避坑（阴影裁切 / 滚动槽位 / 原生语义）

### 1. 阴影与祖先裁切

- 症状：投影只露半边、hover 后投影边缘突兀切线、透明/无边框窗口四周硬截断、圆角容器某帧突然变直角；
- 根因：任意祖先设置 `overflow: hidden/auto/scroll`、`clip-path`、`contain: paint`，或受透明窗口物理边界限制，超出矩形的像素被硬性裁剪；
- 外扩公式：右侧约 `offsetX + blur + spread`，左侧约 `-offsetX + blur + spread`，顶底同理，多层叠加取各侧最大外扩；元素边缘到裁切祖先内壁距离必须 ≥ 该侧外扩量；
- 解法：圆角裁切放内层、阴影光效放外层；滚动容器内壁按投影方向预留 padding；透明图片先核对真实有色像素边界；无边框透明窗口（Electron `transparent: true` / Tauri 对应配置）必须把窗口物理尺寸与 CSS 外层留白同步放大；hover、展开、弹层激活等所有落点状态都要重新审计；
- **严禁无脑把所有 `overflow: hidden` 改成 visible**：它常承担防布局撑破、隔离上下文或维持圆角的职责，精确定位只修复真正冲突的两层。

### 2. 动效中间帧与圆角遮罩

- 文字升起过渡中途下部遮罩露水平硬线 → 用与位移曲线同步的渐变羽化遮罩（Gradient Mask）代替生硬矩形裁切；
- `clip-path: inset(...)` 默认直角矩形，不继承 `border-radius`；需保留圆角时显式写 `round` 参数（`clip-path: inset(0 round 12px)`），四角曲率与宿主吻合；
- Sticky 定位在复杂弹性布局中可能物理屏幕跳帧 → 用平台原生 Sticky 约束，以真实滚轮在合成器绘制帧下检验平滑度。

### 3. 弹窗背景跳动与滚动槽位

弹窗打开时 body 被注入 `overflow: hidden`，系统滚动条瞬间消失导致页面右突十几个像素，关闭时反跳。解法：真正的根滚动容器配置 `scrollbar-gutter: stable` 保留槽位，或采用成熟组件库内置补偿机制；严禁全局手写不准确的 `padding-right` 计算。

### 4. 三种“原生”层级区分

1. 操作系统原生控件：系统窗口边框、文件选择器、系统级上下文菜单；
2. 渲染引擎原生行为：鼠标滚轮、触控板惯性、文本选择范围、焦点导航环、原生滚动条；
3. 组件库封装组件：第三方 Modal、Select、ScrollArea、Resizable 分栏。

严禁把组件库自定义 DOM 混同为操作系统原生组件，反之亦然。复杂弹窗、伸缩分栏、拖拽交互坚决复用成熟库。

### 5. 焦点管理与历史返回定位

- 发送键默认 Enter，换行 Shift+Enter；组字期间 Enter 仅确认候选词，不触发提交；
- 从详情页返回列表/对话主视图时，依靠数据项唯一 ID 或精准记录的 `scrollY` 恢复视口；避免盲目 `.focus()` 把列表卡片暴力顶到视口最上方并留下刺眼焦点框。

### 6. 严防“修改未生效”盲区

- 有编译打包步骤的桌面工程，源码修改后必须重新构建，确保运行的是最新可执行产物而非历史快照；
- 同一套代码支持 Web 与桌面多端时，Web 开发服务器预览不能替代 Electron/Tauri 真实系统窗口行为，必须在对应桌面环境终验。

### 7. 窗口外壳与原生语义

- 标题栏区域高约 40–46px 为设计基准，遵循平台原生窗口规范；窗口阴影与圆角交给操作系统现代窗口管理器（Windows 11 DWM / macOS Quartz），避免自绘双重装饰框冗余错位；
- 区分无边框沉浸式窗口拖拽区（`-webkit-app-region: drag`）与可交互控件区（`no-drag`），拖拽区内严禁放置可点击或可输入组件；
- 托盘悬浮窗口必须实现：失焦（blur）即时收起、外围透明光晕渲染余量、点击托盘图标状态切换防抖；
- 图标多尺度适配：连续曲率平滑圆角（Squircle），外角透明无直角白边；重点测试 16/24/32px 任务栏小尺寸识别度与 256/512/1024px 高清展示。

## 十一、动效决策、模式词典与加载态

### 动效目的优先

交互动效为传递状态与空间因果服务，拒绝为修饰无故加动画：确认动作反馈、提示状态迁移、表达空间来源、维持对象连续性。动效执行期间不能阻塞正常交互与快速连续击键；弹簧曲线的适用边界见本节“弹性（Spring）边界”。

### 动效频率决策（先判断该不该动）

写任何动效前先按使用频次决策，频次越高越要砍掉动画：

| 使用频次 | 决策 | 典型对象 |
| --- | --- | --- |
| 每天 100+ 次 | **永不动效** | 快捷键触发、命令面板开合、命令面板开关 |
| 每天十几次 | 去掉或大幅削弱 | 悬停效果、列表导航切换 |
| 偶发 | 标准动效 | 弹窗、抽屉、Toast |
| 极少 / 首次 | 可加趣味 | 新手引导、反馈表单、庆祝反馈 |

- **键盘触发的动作绝不动效**：一天重复数百次，动画会显得慢、有延迟、与操作脱节；高频开合面板以瞬时显隐为最优体验。
- 动效目的必须能回答“为什么动”：空间连续性（Toast 同方向进出）、状态指示、操作解释、按压反馈、防止突兀跳变；若只为“好看”且用户高频见到，删掉。

### 时长、缓动与性能铁律

- **时长细分基准**：按钮按压反馈 100–160ms；Tooltip / 小弹层 125–200ms；下拉 / 选择器 150–250ms；弹窗 / 抽屉 200–500ms；营销或解释性动画可更长。**UI 动效常规控制在 300ms 内**，弹窗、抽屉、底部抽屉、Toast 为文档化例外（弹窗/抽屉最长 500ms，Toast 可取约 400ms `ease`）。180ms 的下拉比 400ms 显得更跟手；加载转圈转得快一点，相同真实耗时下用户也会觉得加载更快。
- **缓动决策树**：进场 / 离场 → `ease-out`（起步快、反馈即时）；屏内移动 / 形变 → `ease-in-out`（自然加减速）；悬停 / 颜色变化 → `ease`；匀速循环（跑马灯、进度条）→ `linear`；默认落 `ease-out`。
- **自定义曲线 Token**：内置缓动偏软、缺少力度，UI 采用下列强曲线：
  ```css
  :root {
    --ease-out: cubic-bezier(0.23, 1, 0.32, 1);      /* UI 进场/反馈 */
    --ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);  /* 屏内移动/形变 */
    --ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);   /* iOS 风格抽屉 */
  }
  ```
- **禁用 `ease-in` 做 UI**：起步慢会让界面显迟钝；同为 300ms，`ease-in` 在用户最关注的起步时刻延迟运动，比 `ease-out` 体感更慢。
- **性能属性铁律**：动画只改 **位置（transform: translate）、大小（transform: scale）、透明度（opacity）** 三个合成器属性，严禁动画 `top/left/width/height/margin` 触发布局重排；长列表与高频动效跑在合成器线程，页面才不卡。
- **缩放起点**：弹窗/卡片入场从 95% 大小缩放到原样即可，**不要从零（0%）放大**；退场收敛幅度与速度略大于进场。
- **弹性（Spring）边界**：到终点冲过头一点再弹回的果冻弹性，只用于点赞、弹窗出现等想有趣一点的位置；其余场景少用，用多了显得晃。回弹幅度克制（bounce 0.1–0.3），多数 UI 避免明显回弹。Spring 适合带惯性的拖拽、可中途打断的手势与装饰性鼠标跟随；被中断时保持当前速度平滑反向，而 CSS/keyframes 会从零重启。拖拽撤销、可中断手势优先 Spring，纯确定性位移动画用 CSS transition。

### 无障碍减弱动效双层守卫

同时监听属性 `[data-reduce-motion="true"]` 与媒体查询 `@media (prefers-reduced-motion: reduce)`；开启减弱动态效果时瞬时切换状态或极简透明度渐变，严禁大幅位移与连续扫光。

### 骨架屏双模动效契约

- **扫光参数**：2.0s / linear / 105° 倾角；RTL 语言环境自动翻转 255°；

### 加载态动效选型原则

等待态动效先分清"进度可知"还是"进度不可知"，再选模式：

- **进度可知**（资源下载、上传、列表/任务完成度）：必须用进度型——数字预加载、进度环、波浪/胶囊进度条；进度绑定真实数据源，**禁止匀速假进度条跑满**。
- **进度不可知**（后台请求、AI 思考、短时等待）：才用纯装饰循环型（融球、轨道、波形条、折叠方块等），且不伪装成进度。
- **主题化优先**：与品牌名、品类物件相关的加载（品牌名注水、咖啡杯冒热气）优先于通用转圈；元素必须与业务相关，不堆砌无关吉祥物。
- **时长克制**：启动闪屏总时长不超过 1.5 秒；动画结束不得拖长真实加载——不能让用户为了看动画多等一秒。
- **性能与降级**：优先 SVG 描边、transform/opacity；融球模糊滤镜等重特效在低端机降级为普通圆点；减弱动态效果处理统一遵循本节“无障碍减弱动效双层守卫”。

### 附件卡片原生视图过渡

输入框附件（文档、截图、代码片）增删换位接入 Chromium 原生 View Transitions API：每个卡片 `view-transition-name` 唯一，`@starting-style` 弹性膨胀入场，`.cds-attachment-out` 物理位移动态退场；`@supports (view-transition-group: contain)` 局部容器隔离渲染，无需手写复杂 JS 测距动画库。

### 动效工程细节

- **可中断 UI 用 transition，不用 keyframes**：Toast 增删、开关切换等可被快速再次触发的元素，CSS `transition` 可在中途被新动作重定向；`@keyframes` 被中断会从零重启，动态 UI 优先 transition。
- **crossfade 不顺时用 blur 弥合**：两态交叉淡化怎么调缓动时长都别扭时，过渡期间叠加 `filter: blur(2px)`，把新旧两态混为一体，避免看到两个对象重叠切换；blur 保持 20px 以内，重模糊在 Safari 代价很高。
- **进场状态用 `@starting-style`**：现代 CSS 优先用 `@starting-style` 声明入场初始态，替代 `useEffect` 挂载后再置 `mounted` 的旧模式；浏览器不支持时回退 `data-mounted` 属性模式。
- **位移用百分比而非硬编码像素**：`translateY(100%)` 按元素自身高度移动，随内容自适应，抽屉、Toast 隐藏态优先用百分比，避免写死像素导致高度变化后错位。
- **hover 动画必须加触屏守卫**：触屏点按会误触发 hover，所有悬停动效包在 `@media (hover: hover) and (pointer: fine)` 内；触屏以 Active 按压态为准。
- **非对称进出场节奏**：需要用户做决定的按压阶段慢（长按删除 2s `linear` 走满），系统响应的松开阶段快（200ms `ease-out` 回弹）；通则：用户判断处慢，系统响应处快。离场整体比进场更快更轻。
- **错峰节奏**：一组条目错峰入场，项间延迟 30–80ms、非均匀递增；错峰纯属装饰，**严禁阻塞交互**，条目过多时限流错峰范围。
- **clip-path 遮罩动效**：`clip-path: inset(top right bottom left)` 做矩形遮罩，各边从对应方向“吃掉”元素；典型用法——Tab 无缝色彩过渡（复制标签列表，激活副本裁剪只露当前项）、长按删除进度覆盖层、滚动进入视口的图片揭示、左右对比滑块。需保留圆角时显式写 `round` 参数。

### Zero-JS 纯 CSS 滚动驱动遮罩

长对话流/消息容器滚动边界渐变遮罩，传统 JS 监听 scroll 或 IntersectionObserver 频繁测距会造成 Layout Thrashing。现代 Chromium 升级为 CSS 滚动驱动动效：Houdini `@property` 注册属性，合成器线程 `animation-timeline: scroll()` 驱动，达成 0.0% CPU、0ms 主线程阻塞。

## 十二、弱网、低算力与户外降级

1. **户外高对比度**：核心文本对比度 ≥4.5:1，禁用 `text-gray-400`/`#999` 极浅灰，眩光下字形仍清晰；
2. **千元机低算力降级**：非旗舰禁用全屏大面积 `backdrop-filter: blur` 与多重 JS 弹簧；动画用 GPU 加速的 transform/opacity，时长 150–200ms，复杂手势阻尼降级标准 CSS 缓动；
3. **大指腹防误触**：底部核心按钮高 ≥48px（h-12/h-14），相邻独立点击项间距 ≥12px；
4. **弱网离线**：点击保存/收藏/点赞后立即乐观更新（Optimistic UI）；失败弹明确 Toast 并自动撤销状态或常驻“重试”悬浮条，严禁整屏蒙层死锁转圈。乐观更新先快照上一版基线状态，失败时按基线回滚，而非只回滚表面数值。
5. **避免父级 CSS 变量触发全量重算**：父级改动一个 CSS 变量会触发其所有子元素样式重算；抽屉长列表中拖拽位移直接写在元素自身 `transform` 上，不要在容器上更新 `--swipe-amount` 之类变量波及全部子项。
6. **繁忙时 CSS 合成器动画比 JS rAF 更稳**：`transform/opacity` 的 CSS 动画跑在合成器线程、脱离主线程；主线程同时加载页面、跑脚本或绘制时，`requestAnimationFrame` 驱动的 JS 动画（含 Motion 的 layout 布局动画、惯性拖拽、`onUpdate`/`transformTemplate`、逐帧 motion value）更容易掉帧。确定性动画用 CSS，动态可中断动画才用 JS；需要 JS 控制时优先 WAAPI（`element.animate`），兼具 CSS 性能与可中断性。

## 十三、组件架构与状态管理阶梯

### 1. 组件组织原则

- **组合优于配置**：用插槽/子组件组合（`Card > CardHeader > CardTitle`），避免一个组件靠成堆 `title/headerVariant/bodyPadding` 配置项拼装。
- **单一职责**：一个组件只做一件事；单文件组件超过 200 行应拆分。
- **数据获取与展示分离**：容器组件负责取数、处理加载/错误/空态；展示组件只接收 props 渲染，不直接耦合数据源。
- **就近共置**：某组件的实现、测试、自定义 Hook、类型定义放在同一组件目录下，便于内聚维护。

### 2. 状态管理最简阶梯

按从简到繁选型，能用前者就不上后者：

1. 本地状态（`useState`）：组件专属 UI 状态；
2. 提升状态：2–3 个兄弟组件共享；
3. Context：主题、登录态、语言等读多写少的全局上下文；
4. URL 状态（searchParams）：筛选、分页、可分享的界面状态；
5. 服务端状态（React Query / SWR 等）：带缓存的远端数据；
6. 全局 store（Zustand / Redux 等）：跨应用共享的复杂客户端状态。

- **props 钻取不超过 3 层**：若中间组件透传自己并不使用的 props，应引入 Context 或重构组件树，而不是层层下传。

### 3. 工程验收红旗

- 组件超 200 行未拆分；出现内联样式或任意像素魔术值；
- 缺失错误态 / 加载态 / 空态；未做键盘导航测试；
- 颜色成为状态唯一指示；整体呈现通用“AI 观感”（紫色渐变、超大卡片、模板化布局）。
